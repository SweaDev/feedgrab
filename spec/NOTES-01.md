# NOTES-01 — implementation decisions log
- T01: Biome 2.6 formats Markdown; `**/*.md` is excluded in `biome.json` so formatting never shifts the spec line references — PLAN L28 forbids spec edits.
- T01: Installed majors: ai 7, zod 4, typescript 7, @biomejs/biome 2.6, happy-dom 21, @playwright/test 1.64. Peer ranges use `>=<major>`.
- T01: `tsconfig.json` adds `resolveJsonModule` (needed for the package.json import in T30) and `skipLibCheck` (third-party d.ts noise) — not listed in PLAN L154-158 but harmless.
- T05: happy-dom 21 disables JS evaluation, CSS and iframe loading by default (the `disable*` flags are deprecated), so `parseHtml` only sets `disableJavaScriptFileLoading`, `disableComputedStyleRendering` and the user agent. `doc.write(html)` keeps `doc.URL === url`.
- T05: Capability probe (happy-dom 21): `:scope >`, `:has()`, `createTreeWalker`, `compareDocumentPosition`, `MutationObserver` on `getWindow(doc)` and `createHTMLDocument` + `innerHTML` all work. **No native `document.evaluate`** → `parseHtml` registers the `xpath` package. Workaround: the engine must call `xpath.parse(expr).select({ node, isHtml: true })`, because plain `xpath.select` treats XHTML-namespaced elements as non-matching for name tests.
- T08: `isStableToken` adds one rule to the PLAN L248-255 list: a `_`/`-` separated segment of ≥ 5 characters mixing letters and digits is a hash (e.g. `_post_1x9ab_12`). The PLAN regexes alone classify CSS-modules names as stable, which contradicts the T08 test table and the `css-modules` fixture.
- T08: Added `isSameKindSig(a, b)` (same-kind check on `sigL1` strings; classless signatures of one tag match) for the engine's signature-outlier test, which only has `dominantSig` as a string.
- T09 (spec-sync): `@medv/finder` v4 reads the globals `document.body` (eagerly, in its defaults), `Node.ELEMENT_NODE` and `CSS.escape`, so it throws on parsed documents in Bun/Node and would only work in browsers — breaking Bun/browser parity (SPEC §14). `containerSelector` therefore uses a local, deterministic finder-style search (stable `#id` → stable classes → `STABLE_ATTRS` → tag+classes → tag, then ancestor paths with `>`), with the `nth-child` path fallback. `@medv/finder` was removed from `dependencies`.
- T10 (spec-sync): `NAV_SELECTOR` drops `aside` from the PLAN L282 list. The `two-feeds` fixture (PLAN L607) puts a real feed in `aside.updates`, which a full nav penalty would push below the threshold. Sidebar link lists (e.g. social-feed "Trending") are still penalized by the 0.5 short-text/single-link rule and score ≈0.32. Weights and threshold are unchanged. Scores: social 0.89, search 0.74, product 0.90, blog 0.75, news 0.70 / updates 0.70, thread 0.78, css-modules 0.75, stream 0.69, list 0.69, placeholder 0.58.
- T15: AI SDK v7 still exports `generateObject` but recommends `generateText({ output: Output.object({ schema }) })` (and `instructions` instead of the deprecated `system`). `structured.ts` uses that, reads `result.output`, re-validates with zod, and treats `NoObjectGeneratedError`/`NoOutputGeneratedError`/`TypeValidationError`/`JSONParseError` as schema failures (one repair retry); other errors → `LLM_UNAVAILABLE`. Test mocks use `MockLanguageModelV4` from `ai/test`.
- T15: `handleLlmRequest` is implemented in `src/llm/handle.ts`; `llm/index.ts` (entry) and `run-model.ts` re-export it, keeping entry files to re-exports only (PLAN L123).
- T21 (spec-sync): Added `LISTENER_ERROR` to `ErrorCode` — `feed:error` needs a `FeedDetectorError` when a consumer's event listener throws (PLAN L401), and no PLAN L205-207 code fits.
- T21: `itemId(el, baseUrl, minItemTextLength = 10)` picks the permalink without `:has()` (manual `querySelector('time')` check) so the same code works in every DOM; `:has()` is supported by happy-dom anyway (T05).
- T23: `FeedObserver` uses one `MutationObserver` on `doc.documentElement` (childList, subtree, characterData) instead of one per container plus a separate body observer for re-mounts. Records are still coalesced per microtask into `processBatch()`, which only re-resolves containers when one disconnected, none exist, or nodes were added outside every container. A per-container observer cannot see its own container being replaced, so this is simpler and handles re-mounts in the same batch (re-attached items only emit `item:updated`). Feeds that were lost at `openFeed` time are also watched and picked up if their container appears.
- T25: Without an `llm` backend, `openFeed` treats `llm-text` rules as non-matching (items `kept`) instead of leaving them `pending` forever.
- T30: The core also exports `VERSION` (from T01) besides the PLAN L585-589 list; `api.test.ts` asserts it equals `package.json`'s version. `src/browser.ts` imports `package.json` for `version`, so it is excluded from `tsconfig.build.json` (outside `rootDir`; `./browser` has no `.d.ts`).
- T30 (spec-sync): All zod schemas (`profile/schema.ts`, `llm/contract.ts`, `llm/config.ts`) use `zod/mini` (zod v4's tree-shakable API). With full `zod` the IIFE bundle was 146 KB (> 120 KB budget, PLAN L191); with `zod/mini` it is 80.5 KB. The AI SDK accepts the mini schemas in `Output.object` (T15 tests still pass).
